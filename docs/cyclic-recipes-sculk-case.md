# 循环案例：截图中的材料—流体回收链

日期：2026-11-08。分支：feature/cyclic-recipes-1.20.1。
本文为截图案例分析，不代表运行时循环执行功能已经实现。

## 证据与不确定信息

用户提供两张 JEI 配方截图。第一条标注 120 秒、1.92K EU/t，第二条标注 10 秒、120 EU/t。按图片读取到批次数量，但没有悬停名称/注册 ID，不能仅凭图标锁定所有物品和流体身份。

已读取本地 gtceu-1.20.1-1.4.4.jar、[GTLCore]gtlcore-1.2.3.0-fix9-循环箭头上移修复.jar，并参考本地 GTLCore 源码副本。GTCEu 配方类中有 calibrated_sculk_sensor 等相关内容，GTL 源码有幽匿方块的其他获取途径，但尚未定位截图中的完整两条生成配方。需要运行时注册配方或整合包 server_scripts 核实，不能以名字搜索未命中证明配方不存在。

下面使用符号，避免把图标相似误当成相同材料：

- Q：第一张实际消耗、第二张返还的蓝黑色材料，按截图关联暂视为同一材料，待注册 ID 核实。
- F：第一张输出 10B、第二张输入 10mB 的深色流体，暂视为同一流体，待 ID/NBT 核实。
- P：第一张输出 64 个的方块。
- S：第二张额外消耗的绿色物品。不能忽略，亦不能未经核实把它与 P 等同。
- L1、L2：第一张各消耗 1B 的两种流体。
- T1、T2：第一张各显示 64 且明确标注不消耗的两个物品，属于预置条件。
- U：第二张其余输出槽；具体种类、数量及概率尚未核实。

## 按截图批次建立关系

第一步：64Q + 64泥土 + 1000mB L1 + 1000mB L2 → 64P + 10000mB F。
机器需预置 T1、T2；不将它们当成每批耗材。

第二步：1S + 10mB F → 1Q + U。

这是两条配方间的 Q/F 周转循环，而不是图中 T1/T2 的不消耗工具循环。

## 条件性净量核算

假设 Q、F 身份一致且第二步必定返还 1Q：

- 第一批消耗 64Q，需要执行第二步 64 次才能恢复 64Q。
- 因此须从第一步产出的 F 中保留 64×10=640mB。
- 可交付的净 F 是 10000−640=9360mB，即 9.36B。
- 外部输入仍有 64 泥土、两种各 1000mB 的流体，以及第二步的 64S。
- 净输出包含 64P、9360mB F 和第二步的副产物；U 未核实前不承诺其精确产量。
- 64Q 仅在本生产单元内部消耗并恢复，不能同时把它声明为交付给外部的净产物。

这些数值只适用于截图所示批次。若截图存在配方显示倍率，或底层配方有更小批次，最小种子与调度单位需要按真实注册数量重算。

## 启动与执行顺序

可选启动条件：

1. 先准备 64Q，执行第一步，再用保留的 640mB F 和 64S 执行第二步，恢复 64Q。
2. 若有 640mB F 和 64S，可先执行第二步建立 64Q，再执行第一步；后续仍需保持同等周转储备。

仅有 10mB F 在当前截图批次下不能自动推出可启动：它只换到 1Q，第一步仍需 64Q，除非底层存在较小批次或其他获取途径。

如果第二步的 S 也必须由 P 或其他内部产物制作，应将对应配方纳入组内，重算 P 的净输出、种子与可执行顺序；目前两张截图不能证明这条额外关系。

## 对 AE2 暴露的行为

可行的生产组可以把两步的净行为提供给 AE2，但必须真实执行回收：

外部输入（泥土、L1、L2、S）→ 外部输出（P、净 F、经核实可承诺的 U）。

Q 的周转与 640mB F 回收份额由内部缓冲保留，不能被主网络的其他 CPU 或输出任务提前拿走。若只是删除样板中的 Q 输入而没有内部回收控制，机器仍会缺料，并不能解决问题。

当用户要求额外交付 Q 时，必须重新计划。上述净周期的 Q 增量为零，不能在维持储备的同时凭空提供额外 Q；需要消耗额外种子、减少别的交付项或加入其他路径。

## 建议的功能落点

- 循环分析页：显示参与机器、内循环材料、外部耗材、种子需求、毛产出/回收保留/可交付净量，以及未验证的身份和概率。
- 循环生产组：明确绑定两台或多台实际机器，拥有内部物品/流体缓冲；按可执行顺序调度，不依赖全局删除 AE2 递归检查。
- 并发：同一组可复用一份种子串行执行多轮；额外并行批次需额外种子或排队，不能按两个 AE2 任务重复计算同一份储备。
- 失败：缺 S、机器堵塞、断网、区块卸载时保留已实际执行的进度和材料；报告停在哪一步，不伪造回滚。
- 概率：截图未显示概率不等于已确认必定返还。真实配方确认后，才决定是否可按固定净产出规划；概率回收需补种和失败策略。

当前可以确认这类循环具备“以少量内部周转材料支撑净生产”的解决方向。需要补充 server_scripts 或运行时配方数据，以确定完整身份、数量、概率及 S 的来源后再实现运行时功能。
