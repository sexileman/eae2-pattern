# 1.20.1 合并前回归审查

日期：2026-11-08。来源：ui-polish-1.20.1；目标：1.20.1。候选版本：6.3.4。

## 结论

发现的性能及界面边界问题已修复。代码审查及自动检查范围内，没有剩余阻断合并的问题。此结论不等同于真实整合包的高并行压测或逐像素游戏内验收。

## 本次发现与修复

| 问题 | 影响 | 修复 |
| --- | --- | --- |
| 通配符条件变化后立即调用已选计数，早于 200ms 防抖结束 | 每次按键仍可能遍历旧匹配集并读取源配方 | 等待/筛选期间不执行已选计数；完成后再缓存结果 |
| 普通编码在分片筛选未结束时仍推进预览请求 | 可能对旧焦点发请求，产生无效工作及过期展示 | 等待筛选完成后才推进预览计时 |
| 动态规则先构造全部所选规格再只保留一条 | 不必要的列表、数量及 NBT 对象分配 | 找到首条有效机器锚点即停止构造；服务端仍按完整规则、机器类型和例外集合校验 |
| 窄列表材料计数按固定宽度显示 | 小 GUI 尺寸下可能侵入箭头/输出列 | 计数按实际列宽限制；空间不足时由详情展示完整材料 |
| 极端数量倍率计算或规格校验在预览/提交异常处理之外 | 异常配方可能让点击或 tick 直接失败 | 将规格构建纳入参数/算术异常处理，显示失败提示 |

## 性能、内存及数据路径检查

- 主列表和通配符列表共用 RecipeListRow，按可见范围绘制，不为所有配方创建控件；输入、箭头、输出列共用 RecipeStripLayout。
- 两页搜索均采用单调时钟 200ms 防抖，忽略未变化文本。普通过滤每 tick 约 4ms，通配符过滤约 3ms/96 项；这些是软预算，单次模组配方读取仍可能超过预算。
- StackVisuals 屏幕局部物品缓存上限 512；通配符解析结果按当前配方集合持有，关闭整个编辑流程后可回收，未新增静态全量物品缓存。
- WildcardRuntime 的展开缓存为 32 项/约 8MB 数据权重，读取缓存为 1024 项/约 4MB 数据权重；权重并非 JVM 堆内存精确测量。重载和停止时有清理路径。
- 生成及固定收录在服务端分片执行，写入阶段普通空白与通配符空白使用不同键。每项取出耗材后，插入失败有同种耗材退款路径，退款失败退入背包或掉落。
- 批次重组有分片、条目及超时限制，断线/停服清理；手持写入继续检查物品指纹、数量及位置，已编码数据不计入空白通配符库存。
- 通配符缓存命中后仍为提供方创建独立的 AE2 配方详情对象，避免跨供应器共享可变对象；实际规划成本仍随配方数量增长。

## UI 一致性及近期回归检查

- 两页列表共用行高、勾选框、悬停/选中状态、概率/跳过标记和固定材料列；详情数量、流体单位、电路配置与不消耗状态保留。
- 原始配方/编码预览均为单击切换；重复教学移至指南，错误/概率/预置材料提示保留。
- 普通页不再跳转通配符配置；底部库存/网络状态左对齐。
- 更多菜单使用实际动作枚举，紧凑/正常窗口的八项菜单全部命中检查通过，避免旧九项越界崩溃。
- 编码按钮初始化、tick、提交及完成路径均经过 updateButtons，重新赋予“编码 N 张样板/正在编码”文字。
- 原创空白/已编码图标、模组 logo 及 JEI 入口一致；AE2 原生指南解析和物品目标元数据检查通过。
