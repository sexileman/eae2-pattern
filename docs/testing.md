## 4.1.0 启动报告回归

报告中的根因为 `ModLauncher service does not currently support retrieval of untransformed bytecode`，发生于兼容插件调用 `getClassNode(name, false)`，不是由移除原模组导致的缺类错误。

使用实际 Mixin 0.8.5 的 `MixinLaunchPluginLegacy` 提供器，测试仅替换其 transformer-loader 回调，不启动游戏：

- 旧的 false 参数会抛出与日志相同的 IllegalArgumentException。
- 生产插件改用该提供器支持的单参数方法；目标缺失时返回跳过，目标存在时能读取接口。
- 同样经过实际提供器验证 GTL 成对启用、缺失半侧后的稳定跳过，以及普通 AE2 路径不请求可选字节码。
- 可选探测的 IO/参数/状态/链接异常将记录日志并跳过，不向 Mixin 准备阶段传播。

这比单独检查 jar 的接口签名多覆盖了本次出错的提供器路径，但仍不代表整个整合包已经完整启动。

## 安装与自动启用

1. 客户端和服务端仅替换旧 EAE2 包为通用 6.2.0；原 GTLCore、GTCEu、ExtendedAE 无需替换。不要同时安装同一模组的旧包或旧 standalone 包。
2. 无 GTL/GT/原通配符模组时，确认基础 AE2+JEI 与独立通配编辑器正常，缺少类不会触发可选适配。
3. 使用提供的原始 GTLCore 1.2.3.0-fix9、不装原通配符时，确认通配符总成仍注册，并接受 EAE2 新样板。
4. 加装原通配符后，检查总成按物品分别展开两种样板，无重复展开；普通和 ExtendedAE 供应器也分别处理。
5. 前一版修改过 GTLCore 的实例也需验证适配可以应用；当前自动检查覆盖其目标签名，不宣称已验证实际启动。
6. 不支持的 GTL 变体应记录跳过日志，不会只启用总成却遗漏展开适配；此类变体保留原模组行为。
7. 检查旧存档方块、库存、v1 绑定数据和 MissingMappings。无机器约束的旧材料规则仍需重新配置，保留原模组时继续走其原接口。

## 独立编辑器

1. 对 GT 工作方块按 U，使用统一入口采集，在工作台点击“通配编辑器 ↗”；小窗口使用更多菜单。对已生成的独立样板右键重开。
2. 输入包含 `$forge:ingots`，输出包含 `$forge:plates`；两侧分别添加排除项，核对命中后拒绝整条配方、编码材料不会被删减。
3. 检查名称、@模组、$标签、&ID、#提示、|、-、引号；切换整侧/逐材料模式。分别限制输入/输出搜索物品或流体，确认该范围仅影响搜索。
4. 搜索是否包括不消耗材料、实际是否编码不消耗材料是不同选项；用配置电路、模具验证两者。
5. 预览页检查全选/取消当前结果、隐藏选择、滚轮、拖动两侧滚动条、具体材料 tooltip、概率小字、数量/单位以及 JEI 跳转。
6. 编码设置检查 ×2/÷2/重置、输出策略、空输入/输出提示；最终视图取服务端实际编码。策略变化后旧预览应被丢弃。
7. 右键重开的样板恢复规则、类别和收录选择；写入手持样板应更新原载体，编码设置中另存到网络则保留原物品。
8. 在最小及常见 GUI 缩放下，检查四页控件、底部按钮与状态不重叠，长文本可从 tooltip 阅读。

## 机器约束、容量和事务

1. 构造 A/B 两台真实机器，同形态锭→板但不同可加工材料。分别从 A/B 类别收录，检查 A 不公布 B 独有的橡胶板配方；分别请求产物验证实际投料和回收。
2. 每台机器分别使用普通供应器、ExtendedAE 块式与面板式供应器、原 GTL 总成。总成保存重载后仍可展开相同数据。
3. 同系列 100、200、2048 条应在字节预算允许时收录到单张；2049 条至少拆成两张。极端大 NBT 可提前拆分，单条过大则明确拒绝，不扣空白样板。
4. 准备完成后再校验实际空白数；不足时全部不扣。准备时离线/切换网络不得继续写原网络，插入空间不足时退款当前空白。
5. 删除/修改源配方并重载，再触发宿主重扫（拔插样板或重启），对应条目不再展开；重新生成恢复。已在途合成任务中的旧计划不会主动取消。
6. 检查普通模式仍正常，原模组保留时旧材料通配符按原规则展开，没有双重展开本模组独立物品。

## 性能边界

- 单张最多 2048 条；压缩载荷 512 KB、解压原始数据 4 MB、NBT 分配记账 16 MB。生成前验证载荷也能被读取，容量不足则拆分。
- 客户端筛选按 tick 约 3 ms / 96 条软预算，列表只绘制可见行；服务端准备按 tick 约 2 ms / 32 条软预算，最终一次压缩仍是同步操作。
- 单类别采集及服务端默认单次上限 8192，组装 16 MB；不是整个网络的总配方上限。
- 大量逻辑配方仍会消耗 AE2 计划器内存，未做真实整合包性能测量。

GTLCore 二进制补丁仅作为 [历史记录](gtlcore-patch.md)，不属于当前安装流程。

## NBT 重置、空白堆叠与 JEC（6.1）

自动检查包含：重置配方使用原生无序合成、单载体输入/单载体输出且结果无 NBT；空白/带 NBT 的堆叠边界；一叠空白编码恰好减一、背包满拒绝、主副手及原位置保护；未安装 JEC 的中文/英文回退。使用整合包提供的 JEC 4.6.3-fix 原 jar 和原字典，在隔离 classloader 实际执行七个匹配用例（全拼、首字母、机器名、大小写、反例和中文原文），不是仅检查接口签名。

1. 对 v1/v2/v3 通配样板分别使用工作台、背包 2×2 和 AE 合成终端，放入一张并取出结果；全部 NBT 清除，规则、编码者与自定义名称不再保留，数量为 1。
2. 对带 Lore、名称和无关 NBT 的载体重置；检查输出和全新空白完全相同，可以与原空白合并堆叠。已空白的载体单独合成仍只得到一张。
3. 64 张空白可堆叠；任意有 NBT 的载体上限 1。Shift 合成多张重置时应逐个消费原载体、数量守恒。JEI 能查看重置配方，拥有载体后配方书解锁。
4. 主手/副手分别拿 64 张空白编码，得到背包中 1 张成品与原手中 63 张空白；再次编码可继续执行。原本仅一张则在原手中更新，背包满也能改写。
5. 拿一叠空白、背包无空位时编码，全部保留；准备时切槽或改变数量，指纹检查拒绝。没有物品掉落或半写入。
