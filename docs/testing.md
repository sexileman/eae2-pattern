# 4.0.0 验证记录与游戏内验收

## 构建及自动检查

本次最终构建通过：221 项领域回归、141 项独立产物/补丁保留/四种提供方组合检查、6 项原包字节码接口契约检查。没有执行实际游戏启动或世界内验收。

Java 17 / Forge 1.20.1。工作区使用缓存 Gradle 8.8 和本地离线依赖完成构建；普通环境可运行：

```powershell
.\gradlew.bat build independentWildcardTest -PcompatModsDir="D:/codex workspace/others/mods"
```

生成：

- `build/libs/eae2-pattern-4.0.0.jar`：独立物品、编辑器和 AE2 供应器适配，不内嵌原模组。
- `build/libs/gtlcore-1.2.3.0-fix9-eae2-wildcard.jar`：基于所提供 GTLCore 输入的定点补丁。
- `gtl-patch-support` 仅为构建中间件，不能安装进游戏。

自动验证范围：

- 输入/输出分别包含与排除、排除优先、整侧与逐材料语义、空搜索范围；原有 JEI 搜索语法、NBT、电路、概率、倍增、分组及详情回归。
- 单张 2048 条压缩往返、拒绝 2049 条、旧 v1 读取、规则清理与网络往返、重复 ID、错误版本、错误计数、压缩大小和解压大小边界。
- 输出 EAE2 jar 不含原模组类、嵌套原 jar 或 GTL 桥接重复类；自身 API、供应器 hook 与独立物品资源存在。
- GTL 补丁只改变指定的两处集成类和可选依赖元数据，逐一对比不相关原始资源/类字节保持一致，补丁源码随构件提供。
- 读取最终重混淆桥接类，用隔离 classloader 构建仅新模组、仅旧模组、两者共存、两者均无四种 fixture，验证启用、识别和展开分流，未安装的提供方类不在该 fixture 中。

隔离 fixture 不是 Forge 游戏启动，也不验证真实机器的物品/流体能力。当前没有启动整合包或生成游戏截图，不宣称已完成以下实测。

## 安装与启动

1. 客户端与服务端同步移除旧 EAE2（含旧 `standalone-gtl` 版），换入 `eae2-pattern-4.0.0.jar`；替换原 GTLCore 为修改版，不同时安装两个 GTLCore。
2. 测试不安装原 `wildcard_pattern` 时，只有 `eae2_pattern` 注册独立物品，GTL 原通配符总成仍注册，没有缺类或依赖错误。
3. 额外测试仅保留原模组、两者共存，以及两者都不安装。原模组的物品继续走旧接口；两者都不安装时总成沿用未启用状态。
4. 旧存档检查原总成方块、库存及已放置样板；移除原模组时检查 MissingMappings 迁移。旧 v1 绑定数据可读；旧无机器约束材料规则需重新选机器配置，不凭空推断类型。

## 独立编辑器

1. 对 GT 工作方块按 U，使用统一入口采集，在工作台点击“通配编辑器 ↗”；小窗口使用更多菜单。对已生成的独立样板右键重开。
2. 输入包含 `$forge:ingots`，输出包含 `$forge:plates`；两侧分别添加排除项，核对命中后拒绝整条配方、编码材料不会被删减。
3. 检查名称、@模组、$标签、&ID、#提示、|、-、引号；切换整侧/逐材料模式。分别限制输入/输出搜索物品或流体，确认该范围仅影响搜索。
4. 搜索是否包括不消耗材料、实际是否编码不消耗材料是不同选项；用配置电路、模具验证两者。
5. 预览页检查全选/取消当前结果、隐藏选择、滚轮、拖动两侧滚动条、具体材料 tooltip、概率小字、数量/单位以及 JEI 跳转。
6. 编码设置检查 ×2/÷2/重置、输出策略、空输入/输出提示；最终视图取服务端实际编码。策略变化后旧预览应被丢弃。
7. 右键重开的样板恢复规则、类别和收录选择；另存新样板后原物品仍在，生成结果写入网络。
8. 在最小及常见 GUI 缩放下，检查三页控件、底部按钮与状态不重叠，长文本可从 tooltip 阅读。

## 机器约束、容量和事务

1. 构造 A/B 两台真实机器，同形态锭→板但不同可加工材料。分别从 A/B 类别收录，检查 A 不公布 B 独有的橡胶板配方；分别请求产物验证实际投料和回收。
2. 每台机器分别使用普通供应器、ExtendedAE 块式与面板式供应器、修改版 GTL 总成。总成保存重载后仍可展开相同数据。
3. 同系列 100、200、2048 条应在字节预算允许时收录到单张；2049 条至少拆成两张。极端大 NBT 可提前拆分，单条过大则明确拒绝，不扣空白样板。
4. 准备完成后再校验实际空白数；不足时全部不扣。准备时离线/切换网络不得继续写原网络，插入空间不足时退款当前空白。
5. 删除/修改源配方并重载，再触发宿主重扫（拔插样板或重启），对应条目不再展开；重新生成恢复。已在途合成任务中的旧计划不会主动取消。
6. 检查普通模式仍正常，原模组保留时旧材料通配符按原规则展开，没有双重展开本模组独立物品。

## 性能边界

- 单张最多 2048 条；压缩载荷 512 KB、解压原始数据 4 MB、NBT 分配记账 16 MB。生成前验证载荷也能被读取，容量不足则拆分。
- 客户端筛选按 tick 约 3 ms / 96 条软预算，列表只绘制可见行；服务端准备按 tick 约 2 ms / 32 条软预算，最终一次压缩仍是同步操作。
- 单类别采集及服务端默认单次上限 8192，组装 16 MB；不是整个网络的总配方上限。
- 大量逻辑配方仍会消耗 AE2 计划器内存，未做真实整合包性能测量。
