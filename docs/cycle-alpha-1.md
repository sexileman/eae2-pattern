# 循环增殖实验版 alpha.1

版本：6.6.0-cycle-alpha.1。构件：eae2-pattern-1.20.1-6.6.0-cycle-alpha.1.jar。
仅在 feature/cyclic-recipes-1.20.1 开发；未合并正式分支。

## 启用与使用

客户端和服务端同时换成该实验版。首次测试使用测试世界或存档副本。实验执行默认关闭，管理员在游戏内运行：

```text
/eae2_pattern config set cycles.experimental_execution true
```

也可以在世界的 serverconfig/eae2_pattern-server.toml 中设置：

```toml
[cycles]
experimental_execution = true
```

将两条真实处理样板放入原供应器，机器配置和不消耗电路等仍按原方案预置。网络中放入启动材料和全部外部耗材，然后在原 AE2 终端请求循环中的 A 或 B。普通原生计划已能完成时不替换；仅原生缺料、捕获到受支持二元循环时尝试实验计划。成功时聊天显示阶段数，确认界面使用计划的全部初始耗材及字节开销；确认提交时原生 CPU 再次提取全部耗材，期间被其他任务取走则提交失败。

关闭开关只阻止新实验计划，已在运行的任务继续按保存状态执行。可通过 AE2 原生 CPU 界面取消；按原生取消机制退回 CPU 内现存材料，在途加工不会凭空回滚。切换回正式版、移除本模组或更换 AE2/CPU 实现前先完成或取消所有实验任务。

## alpha.1 支持范围

- 使用原生 CraftingCPUCluster 执行逻辑的 CPU；扩展其存储器/并行部件可以保留。网络包含尚未适配的独立 CPU 实现时，不产生实验计划，避免误交给另一套执行器。
- 两条原生 AE2 处理样板表示的 A→B、B→A 增殖回路，可附带其他消耗材料及确定性副产物。
- 请求目标必须是 A 或 B 本身，按本次新制作数量交付，并恢复所占用的启动库存。材料键严格区分物品、流体与 NBT。
- 必须保证样板声明的输出都会真实返回；概率输入按样板声明数量占用。概率返还或概率副产物不能作为可靠循环承诺，应先重新编码为准确的确定性输出，否则会停在等待材料状态。
- 外部耗材按整个计划的整数执行次数汇总，先要求已有库存；不自动制作缺失外部材料，不把未来副产物抵扣成现在可用库存。
- 采用可验证的完整整数周转量作为启动量，不保证找到数学上的最小启动组合。启动库存不足或计划超过 512 阶段/100 万次原配方执行时保留原生缺料结果。
- 存在已启用且接口匹配的 EAP 智能倍增时，单个实际投料批次最多合并 64 份原配方，并遵守其配置倍率上限；其他情况使用原版单份投料。供应器拒绝或能量不足时逐步缩小批次；同一批的实际产物全部回流后才发下一批。

尚不支持：上游 C 同时需要循环中的 A/B、一个任务的双交付目标、三种及以上材料回路、输入替代/返还容器、跨循环组联合规划、自动补种与机器故障恢复规划。纯数量核心已覆盖双目标算例，但运行时尚未接入双目标，不作功能承诺。

## 与 EAP 智能倍增的关系

新循环计划在原生缺料规划返回时单独构造，保留原注册配方身份，不把完整任务次数交给全计划倍增再合并。执行阶段通过 EAP 原有 PatternScaler 包装当前批次，沿用其输入输出放大和供应器解包逻辑；寻找供应器使用原配方，pushPattern 使用与实际输入量一致的批次配方。无法识别或关闭倍增时使用原配方单份投料，不把超量 inputHolder 强行交给普通供应器。普通非循环任务仍使用原生及附属模组原来的路径，不修改供应器倍增开关。该路径已经过字节码/API 核对，但 ExtendedAE、EAP、GTL 总成在游戏内的真实投料尚待验收，不等于所有附属供应器都已兼容。

## 必测场景

1. 小量启动 A，请求大量 A，观察 A→B→A 多轮，不能第一批就索要全量循环材料。
2. 改为从 B 启动；交换请求目标。启动量按完整整数周期准备。
3. 两条配方都消耗同一种 X，并带不同外部材料/流体：确认预览合计数量；取走一件必需 X 后重新规划，应该拒绝；确认界面打开后再取走 X，提交应失败。
4. 开启 EAP 智能倍增，比较任务仍按阶段推进；普通任务保持原行为。
5. 普通 AE2 与 ExtendedAE 供应器分别测试；小机器库存拒绝大批后应缩小投料，不扣丢 CPU 输入。
6. 单批只返回部分产物，应继续等待，不提前推进或交付。目标产物中途回流仍留在 CPU 内。
7. 等待回流时保存退出、重进，不能重复投料；断电恢复后继续同一阶段。外部存储满时最终交付等待容量。
8. 取消、机器阻塞、两个 CPU 同时发起请求，检查实际材料守恒；多个任务不能重复占用同一份启动材料。

## alpha.2 类型兼容修复

用户实测已进入 6 阶段循环规划，但在预览摘要阶段收到 GrowthCraftingPlan→CraftingPlan 的 ClassCastException。已直接核查整合包 ae2ct-1.20.1-1.1.1.jar：AE2CraftingPlanSummary.buildEX 对 ICraftingPlan 做 CHECKCAST CraftingPlan，并调用 RecipeHelper.fromCraftingPlan(CraftingPlan)。

现在返回实际的 appeng.crafting.CraftingPlan，循环描述作为对象附件保存，CPU 从该附件取得阶段；不用全局缓存，不移除 AE2CT，也不修改整合包 jar。普通原生计划附件为 null。附件适配与 CPU 适配整体探测，无法支持时不产生实验计划。

新增检查：原生强制类型转换、计划成本字段保留、实际 AE2CT RecipeHelper.fromCraftingPlan 调用、AE2 15.2.16/15.4.10 的计划载体形状与完整适配包装。仍未启动完整 Forge 世界，真实 Mixin 应用和整个任务执行仍需游戏内验收。

alpha.2 自动构建通过：4520 项回归检查、123 项通用包装/接口检查和 37 项整合包接口检查，其中实际调用所提供 AE2CT jar 的摘要构造方法验证原生类型兼容。此验证不包含真实世界内的完整 CPU 执行。
