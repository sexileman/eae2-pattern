# 循环配方支持：可行性与实现边界

基线：origin/1.20.1，b31c48f。开发分支：feature/cyclic-recipes-1.20.1。
日期：2026-11-08。本文为设计调研；尚未实现运行时循环规划或执行，不发布功能 jar。

## 已核实的现状

- 本项目的通配符样板展开为普通 AE2 配方详情，仍由 AE2 合成规划器计算任务；一张样板收录多条配方不会绕开循环检测。
- 检查实际 AE2 15.2.16 映射 jar：CraftingTreeNode.buildChildPatterns 调用父节点 notRecursive；notRecursive 沿祖先检查产物，排除循环路径。请求过程先从模拟库存取料，再寻找可用生产路径。因此不能笼统声称“只要有任何循环就一定失败”，已有中间库存可能使某个有限任务成立，但不代表能反复用少量种子扩产。
- AE2 1.20.1 官方指南明确说明普通自动合成不理解递归生产，并给出带合成卡的发信器驱动独立生产系统这一方案。

## 必须区分的情况

| 情况 | 能否启动 | 应对 |
| --- | --- | --- |
| 无种子，且所有生产路径均互相依赖 | 不可启动 | 报告缺少的初始材料；寻找非循环替代配方 |
| 有种子，有确定性的净目标产出 | 可建立有限批次方案 | 保留种子，按实际可执行顺序推进，外部显示净消耗/净产出 |
| A→B、B→A 完全等量且无额外有用产物 | 可转换但不能扩产 | 不得将其当作可无限增产的来源 |
| 概率返还、概率副产物、条件性工具损耗 | 无法给出必然完成保证 | 不使用期望值承诺固定产量；明确限额、失败/补种和停止策略 |

种子不一定是不消耗工具。真正会在生产中消耗、稍后返还的材料，不能从样板输入中删除来伪装成催化剂。

## 推荐架构：循环生产组

1. 诊断层：对选择的实际配方或网络已发布样板建立材料依赖图，检测强连通分量；循环候选不等于可执行生产计划。忽略无消耗工具的依赖边，但保留数量、流体、NBT 和机器身份。
2. 计划层：由用户确认内部材料、种子储备、目标产物及配方集合。对确定性配方做整数数量的前向可执行模拟，检查中间库存始终非负、保留种子，并限制搜索步数、分支数及规划时间。净量抵消不能代替顺序可执行性检查。
3. 执行层：需要实际循环控制器或等价协调机制，拥有隔离的内部缓冲和机器/供应器绑定。不能把多机器步骤直接编码进普通单机器样板后假定它会自动路由。
4. AE2 集成层：向 AE2 广告该生产组的净输入和净输出，内部依次将材料送往正确机器，完成后只交付可承诺的净输出。对没有外部输入的持续生产，需要发信器式接口或专门集成，不能伪造普通 AE2 空输入处理样板。
5. 并发与恢复：种子按生产组独立占用，禁止两个 CPU 共用同一份种子；断网、机器阻塞、超时及区块卸载时保留进度和实际材料，不凭空回滚已执行的机器加工。

普通 AE2、ExtendedAE 和 GTL 总成的现有“展开样板”适配不等于协调循环执行。需要分别验证其路由、回收、并行及取消行为。

## 确定性示例

机器 1：A + X → B。
机器 2：B + Y → 2A。

从 1A 种子启动，一个循环依次得到 B、再得到 2A；保留 1A 种子，对外交付 1A。外部净行为可表示为 X + Y → A。此表示只有在内部真实执行两步、保留种子且返回规则确定时成立。

若改为 B + Y → A，则 A 只被恢复，不会净增；不能把相同的净产物 A 承诺给外部。

## 性能约束与首版建议

- 只分析明确选择的配方集或网络中实际已发布的样板，不在每帧扫描整个 JEI/GT 配方库。
- 按需分片建图，使用材料键到生产配方的倒排索引；图规模和搜索预算显式设限。依赖图可线性检测循环，但带替代配方和数量的可执行规划不保证线性时间。
- 首版限定确定性处理配方，严格区分物品/流体/NBT，用户明确指定种子和机器组。概率循环不自动承诺完成。
- 用真实配方验证后，才能确定自动配置范围和 GUI。至少覆盖无种子、零净增长、多步放大、流体/NBT、电路、概率损失、并发争抢、断网和机器阻塞。

## 待用户提供的必要实例

需要一组实际配方的机器、输入输出数量、概率及初始库存。仅知道“生产 A 要 B、生产 B 要 A”不足以判断是可增长循环、有限转换、回收链还是不可启动依赖。

建议先确认目标是“诊断并给出种子/替代配方建议”，还是“建立自动运行的循环生产组”。后者是新的规划与执行功能，不是简单 UI 或样板格式变更。
